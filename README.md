# 《膳知・AI 营养分析师》

> 一套面向学科竞赛答辩的 **AI 营养健康 Web 应用**：上传食物照片即可识别营养，
> 结合个人身体数据提供 **AI 营养对话**、饮食记录分析、可视化报告与膳食推荐。
> 前端纯静态 SPA（无需数据库），AI 能力通过一个零依赖的轻量 Node 代理接入云端大模型，
> 并内置 **三层降级架构**，保证断网 / 未配置密钥时演示依然不中断。

## 一、核心亮点

| 亮点 | 说明 |
| --- | --- |
| 📷 **AI 食物图像识别** | 调用智谱 GLM-4V 视觉大模型识别食物，自动绑定本地营养条目输出完整营养值 |
| 🎙️ **图像 + 语音多模态闭环** | 识别结果可携带结构化营养数据继续咨询；对话支持中文语音输入和回答播报，不支持语音时自动保留文字交互 |
| 💬 **AI 营养对话助手** | 多轮对话 + **个性化上下文注入**（知道你的 BMI / 今日吃了什么）+ **RAG 知识库增强**，SSE 流式打字机输出 |
| 🛠️ **规划执行型 AI Agent** | 复杂任务先生成 2–5 步结构化计划，再调用 7 个真实数据工具逐步执行、校验并受控重规划；计划和工具轨迹实时可见 |
| 🧪 **反事实营养干预模拟** | 基于真实饮食和本地评分规则比较“控糖 / 补蛋白 / 均衡优化”前后效果，解释为什么某种调整更优，用户确认后才应用 |
| 🫥 **个性化上下文注入** | 每次提问自动带入 BMI / BMR / TDEE / 推荐热量 / 饮食模式 / 今日已摄入营养与健康评分 |
| 📚 **RAG 检索增强** | 提问时从本地 900+ 条营养知识库召回 Top-4 作为「参考资料」注入提示词，并展示给用户核对 |
| 🔄 **永不掉线的三层降级** | ☁️ 云端大模型 → 🧪 Mock 演示 → 🔬 本地可解释引擎 / 本地知识库，任一环节失败自动降级且**带来源提示** |
| 🧮 **解释型识别引擎** | 云端不可用时用 Canvas 像素采样 + 特征规则本地识别，输出「判定依据 + 候选排名」 |
| 📊 **数据可视化** | ECharts 健康评分仪表盘、营养素占比、热量趋势、大屏看板 |
| 🎨 **马卡龙 + Emoji 设计系统** | 六色马卡龙卡片、大圆角柔和阴影、明亮浅色主题、PC 与移动端响应式适配 |

## 二、技术栈

| 分类 | 选型 |
| --- | --- |
| 前端框架 | Vue 3（`<script setup>` 组合式 API） |
| 类型系统 | TypeScript 严格模式（AI 核心链路渐进式迁移，兼容既有 JavaScript） |
| 构建工具 | Vite 6 |
| UI 与样式 | TailwindCSS 3（自定义马卡龙设计系统，无第三方组件库） |
| 图表 | ECharts 5 |
| 状态管理 | Pinia（+ localStorage 持久化） |
| 路由 | Vue Router 4（hash 模式） |
| AI 模型 | 智谱 GLM-4V（视觉识别）/ GLM-5.3-Flash（文本对话），OpenAI 兼容端点；支持 function calling |
| AI 能力 | LLM 对话 + RAG 检索增强 + **Plan-and-Execute Agent** + Function Calling + 图像识别 + 浏览器 Web Speech 语音交互 |
| 服务端 | 零依赖 Node 20（`node:http` + 全局 `fetch`，自研 `.env` 解析），仅用于持有密钥与转发 |
| 交互协议 | HTTP + SSE（`text/event-stream` 流式输出） |

## 三、快速开始

```bash
# 1) 安装依赖
npm install

# 2) 准备配置（可选：不填密钥会自动降级为 Mock 模式，仍可完整演示）
Copy-Item .env.example .env      # Windows PowerShell
# cp .env.example .env           # macOS / Linux

# 3) 启动 AI 代理服务（终端 A）
npm run ai:server                # 默认 http://localhost:8787

# 4) 启动前端开发服务器（终端 B）
npm run dev                      # 默认 http://localhost:5173

# 5) 构建生产产物
npm run build

# 6) 服务端自校验（不联网、不起服务，共 99 项断言）
npm run ai:verify

# 7) 完整质量门禁（ESLint + TypeScript + 构建 + 99 项自校验）
npm run check
```

浏览器打开 http://localhost:5173 即可。页面使用 **hash 路由**，构建产物使用**相对路径**，
可直接双击 `dist/index.html` 打开演示基础功能。但 `file://` 协议下浏览器会拦截 `fetch`，
因此「AI 能力评测」页的报告文件、以及需要代理的真实云端识别 / 对话，请用下面的预览方式体验：

```bash
npm run preview                  # http://localhost:4173，已内置 /api 代理
```

## 六、AI 三层降级架构（稳定性核心）

```
☁️ 云端大模型 ──失败/超时/限流──▶ 🧪 Mock 演示 ──前端纯离线──▶ 🔬 本地引擎 / 本地知识库
   （识别准确）                     （确定性模拟）              （永不掉线 + 可解释）
```

- **识别链路**：GLM-4V 识别 → 失败回退本地 Canvas 特征规则引擎，输出「判定依据 + 候选排名」。
- **对话链路**：GLM-5.3-Flash SSE 流式 → 失败回退本地营养知识库检索作答。
- 降级**静默且带提示**：页面展示来源徽标（`source=cloud/mock/local`）与降级原因，评委一眼可辨。

## 八、如实说明的边界（重要）

1. **本项目没有训练流程**，不产出训练准确率；识别能力来自调用准入的成熟云端大模型，
   因此**不宣称**「识别准确率 99%/95%」这类指标。
2. **本地可解释引擎是规则引擎，不是神经网络**，定位为「云端兜底 + 可解释性素材」。
3. **营养数据不臆造**：模型给出的食物名必须能绑定本地 `FOOD_DB` 条目才输出营养值，
   绑定失败明确提示并禁止写入记录。
4. 项目差异化卖点应表述为 **「个性化 + 可解释 + 永不掉线的三层降级 AI 应用」**，
   而非「自研识别模型」。
