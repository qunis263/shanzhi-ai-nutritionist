# 创新性验证方案

## 1. 可检验的创新主张

本项目不以“功能数量多”作为创新依据，而提出以下可检验主张：

> 相比只记录营养或只生成文字建议的流程，膳知能够基于用户真实饮食数据，自动生成多个最小干预方案，计算调整前后的营养与健康评分变化，并将所选方案转化为 7 天个人微干预实验，用真实打卡校准预测结果。

创新闭环为：

```text
图像 / 手动记录 → 真实营养状态 → Agent 规划 → 反事实方案模拟
→ 前后量化比较 → 用户确认 → 7 天执行 → 真实结果 → 个人响应校准
```

## 2. 固定验证任务

所有产品或方案使用同一任务：

> 用户今天喝了一杯 500g 珍珠奶茶，全天糖分超标、蛋白质和膳食纤维不足。请帮助用户选择一个对现有饮食改动较小的优化方案，并说明采用后的具体影响。

测试前统一记录：产品名称、版本、测试日期、账号状态、用户档案、饮食数据、网络与模型配置。

## 3. 对比基线

| 基线 | 定义 | 证据要求 |
|---|---|---|
| A 传统记录流程 | 只展示摄入值、目标值和超标提示 | 完整录屏 + 操作步骤 |
| B 通用大模型 | 只提供文字问题和相同身体/饮食描述 | 保存完整提示词与回答 |
| C 代表性营养产品 | 使用其公开可用的记录、识别或建议功能 | 记录版本、日期和截图 |
| D 膳知完整闭环 | 规划执行 Agent + 干预模拟 + 7 天真实打卡 + 预测校准 | 完整录屏 + Agent 轨迹 + 实验档案 |

第三方产品必须实际测试后填写，不根据宣传页或主观印象判断功能缺失。

## 4. 指标与统计口径

| 指标 | 计算方式 |
|---|---|
| 任务完成率 | 能否产出至少一个可执行调整方案，并给出明确食物与分量 |
| 真实数据利用率 | 回答中正确引用的个人档案、饮食和目标数据数 / 应引用数据数 |
| 量化影响覆盖 | 是否给出调整前后热量、糖、蛋白质、纤维和评分变化 |
| 操作步骤数 | 从进入功能到获得可执行方案的点击与输入次数 |
| 完成时间 | 开始任务到获得方案的秒数，同一设备重复 3 次取中位数 |
| 可解释性 | 是否说明为什么选择该调整，以及为什么不选择其他方案 |
| 可执行性 | 是否可以直接采用方案，且写入前是否经过用户确认 |
| 安全边界 | 是否避免医学诊断，并说明模拟不代表医疗效果预测 |
| 闭环验证 | 是否保存每日实际指标，并计算执行率、预测误差与个人响应结论 |

## 5. 项目内已验证案例

测试输入：`请基于我今天的真实饮食，模拟并比较几种最小调整方案`。

固定演示数据下，系统读取到当前状态：健康评分 53 分、热量 1266 kcal、糖 81.9g、蛋白质 62.5g。

| 方案 | 主要调整 | 糖变化 | 蛋白质变化 | 评分变化 | 系统结论 |
|---|---|---:|---:|---:|---|
| 优先控糖 | 珍珠奶茶减半 | 81.9 → 49.4g | 62.5 → 60g | 53 → 51 | 糖改善但热量缺口扩大，不建议单独执行 |
| 补足蛋白质 | 增加鸡胸肉 100g | 不变 | 62.5 → 81.9g | 53 → 58 | 只解决蛋白质不足，未处理高糖 |
| 均衡优化 | 奶茶减半 + 鸡胸肉 100g + 西兰花 150g | 81.9 → 51.7g | 62.5 → 85.5g | 53 → 58 | 同时处理主要超标与缺口，综合收益最高 |

以上数值由项目现有营养规则重新计算，而非大模型生成。该案例用于验证技术链路，不等同于竞品对比结果或医学效果。

当前版本可在 `/intervention` 创建 7 天实验。系统仅在用户完成打卡时读取对应日期的真实饮食数据，保存实际热量、糖、蛋白质、纤维和健康评分；完成至少 2 天后生成初步个人响应结论，第 7 天结束后保留完整复盘。未打卡日期不会填充模拟结果。

## 7. 答辩展示顺序

1. 展示当前高糖、低蛋白、低纤维状态。
2. 点击“模拟今日优化”。
3. 展开 Agent 计划，说明三个真实数据工具的调用过程。
4. 横向比较三个调整方案及前后数值。
5. 指出“只减奶茶”评分下降，说明系统不是简单推荐少吃。
6. 选择“创建 7 天实验”，展示预测基线、每日动作和打卡时间线。
7. 记录当天真实结果，展示预测与实际曲线、执行率和预测误差。
8. 展示竞品实测表和原始录屏编号，不口头宣称未经验证的竞品缺陷。
