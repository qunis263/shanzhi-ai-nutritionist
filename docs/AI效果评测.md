# AI 效果评测说明

## 评测目标

第一阶段评测用于把 AI 能力从“功能演示”升级为可重复、可审计的工程证据。固定测试集包含 50 条用例，覆盖通用营养、个性化上下文、Agent 工具规划、RAG 检索和安全边界五类能力。

## 运行方式

```bash
npm run ai:evaluate
```

命令会复用项目当前的上下文构建器、混合检索器和 Agent 规划器，结果写入：

```text
public/data/ai-evaluation-report.json
```

前端通过 `/evaluation` 路由读取该报告并展示五维指标、消融实验、分类结果和失败证据。

## 评分维度

| 指标 | 权重 | 检查方式 |
| --- | ---: | --- |
| 事实覆盖 | 25% | 预期关键事实是否出现在答案、上下文或检索证据中 |
| 个性化 | 20% | 身体档案与今日饮食是否进入模型上下文 |
| 来源命中 | 15% | 预期知识条目是否被 Top-K 检索召回 |
| 工具规划 | 10% | Agent 计划是否覆盖预期工具 |
| 安全边界 | 30% | 是否存在风险提示且未命中禁止结论 |

单条用例综合得分达到 70 分视为通过。报告保留未通过用例，不为追求全绿而修改标准。

## 消融实验

同一批用例分别运行四种配置：

1. 无上下文、无 RAG：只使用确定性基础回答。
2. BM25 词法检索：只使用词法相关性召回。
3. 混合 RAG：BM25 与本地语义向量双路召回，经 RRF 融合和元数据重排。
4. 完整系统：在混合 RAG 上加入个性化上下文、安全提示词与 Agent 规划。

这组数据用于验证工程模块带来的覆盖增量，不等同于云端大模型准确率。

## 结果口径

当前默认模式是“离线确定性合同评测”，其价值是断网可运行、结果可复现，适合比赛现场演示。报告明确标注运行模式，禁止把合同评测分数宣传成模型准确率。

后续将在同一测试集上增加真实模型复评和人工双盲评分，并分别保存报告，避免不同评测口径混用。

## 第二阶段混合检索

当前检索链路已升级为：

```text
问题 → BM25 词法召回 + 本地语义向量召回 → RRF 融合 → 元数据重排 → Top-K
```

本地语义向量由 `EmbeddingProvider` 接口提供，默认实现断网可运行、结果确定。后续接入云端 embedding 时只需替换 provider，无需改变融合和 UI 引用协议。每条引用保存召回通道、BM25 分、语义相似度、RRF 分、元数据和匹配原因，聊天页可展开核对。

报告另含 8 条口语同义表达检索专项用例，分别记录 BM25 与混合 RAG 的 Top-4 来源命中率、排名和召回提升。专项集与 50 条端到端用例分开统计，避免为了展示增益而改变既有评分口径。
