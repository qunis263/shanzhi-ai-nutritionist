## 二、项目介绍（0:30–1:30）

**画面：** 登录页 → 输入演示账号 `shanzhi / 123456` → 点击登录，进入首页。

**旁白：**
> 我们观察到两个普遍痛点：第一，大多数人记不住食物的营养成分，「今天吃了多少糖、多少钠」完全没概念；第二，现有的营养 App 大多只做记录，不会主动给出个性化建议。
>
> 膳知的做法是：用 AI 降低记录门槛、用算法做可解释的营养评估、用大模型做自然语言咨询。
>
> 技术栈方面，前端采用 Vue 3 + Vite + TailwindCSS + ECharts，状态管理用 Pinia；后端是一个零依赖的 Node.js 轻量代理，只负责持有模型 API Key 并转发请求。

## 三、核心功能演示（1:30–5:00）

### 3.1 首页（1:30–2:15）

**画面：** 进入首页，停留在「简洁模式」。

**旁白：**
> 登录后首先是首页。我们采用了「简洁模式 + 专业模式」双视图设计——默认简洁，只展示今日热量进度、饮水进度和一条优先提醒。
>
> 注意这条提醒：先给一句正向夸奖，再只输出一条最需要改进的建议，用人话，不堆砌数字。比如「很棒！今天总热量控制达标，糖分偏高，大概率来自奶茶甜品，建议减少甜饮」。

**画面动作：** 点击右上角「查看详细营养」按钮，展开 8 项指标卡和完整进度总览表。

**旁白：**
> 点击「查看详细营养」切换到专业模式，展开热量、蛋白质、脂肪、碳水、膳食纤维、糖分、钠、饮水共 8 项指标，每条都有实际值、目标值、进度条和四级状态——达标是薄荷绿、偏少是浅鹅黄、轻微超标是暖橙、严重超标的是珊瑚红。

### 3.2 记录饮食（2:15–2:50）

**画面：** 左侧导航点击「饮食记录」。

**旁白：**
> 接下来演示记录饮食。我们按早餐、午餐、晚餐、零食四个餐段组织，食物库内置 915 种常见食物，支持搜索和分类筛选，两列布局方便浏览。

**画面动作：** 搜索「鸡蛋」→ 点击选中 → 调整分量 → 点击「加入早餐」。

**旁白：**
> 比如我搜索鸡蛋，选一个水煮蛋，输入分量 80 克，加入早餐。可以看到「全天营养合计」实时累加了热量、蛋白质等数值，并与每日推荐目标对比。

### 3.3 AI 食物识别（2:50–3:35）

**画面：** 点击左侧「AI 食物识别」。

**旁白：**
> 如果不知道食物重量，或者懒得搜索，可以用 AI 识别。上传一张食物照片，系统会调用智谱的视觉大模型识别食物种类、估算分量。

**画面动作：** 上传一张食物照片 → 等待识别结果出现 → 调整分量 → 点击「咨询 AI」。

**旁白：**
> 识别完成后会给出食物名称、营养成分和健康标签。我可以直接点击「咨询 AI」，系统会把食物、分量、热量、糖和蛋白质等结构化数据带入对话，而不是只传一张无法追溯的图片。当然，也可以继续一键加入饮食记录。

### 3.4 营养对话助手（3:35–4:20）

**画面：** 点击「营养对话助手」。

**旁白：**
> 营养对话助手是项目的核心 AI 能力。和普通聊天机器人不同，它能看到你的身体数据和今日饮食记录，回答会贴合你的情况。

**画面动作：** 展示已带入的识别结果 → 点击麦克风说出问题 → 检查转写文字后发送 → 展示流式输出 → 点击回答下方「播报」。

**旁白：**
> 我可以点击麦克风说出问题，识别结果会先转成可编辑文字，确认后再发送。模型会把刚才的图像识别结果、身体档案和今日饮食一起分析；回答流式输出后还可以语音播报。语音部分使用浏览器 Web Speech API，不宣称自研语音模型；若浏览器不支持或拒绝麦克风权限，会明确提示并保留完整文字交互。
>
> 每条回答下面都有「📚 参考资料」，点击可以展开看到 RAG 检索到的本地知识库内容，确保回答有依据、可追溯。

### 3.5 身体测评 & 营养报告（4:20–4:50）

**画面：** 点击「身体数据测评」→ 再点「营养报告」。

**旁白：**
> 在身体数据测评页，录入身高、体重、年龄、性别和活动强度，系统会计算 BMI、基础代谢、每日总消耗，并推导每日推荐热量和各项营养素目标。
>
> 营养报告页则给出 0–100 的健康评分、优缺点分析、超标项、缺口项和改进建议，整个评分模型是可解释的加权算法。

### 3.6 膳食推荐 & 食物速查（4:50–5:00）

**画面：** 快速切换「膳食推荐」和「食物营养速查」页面（每个 5 秒）。

**旁白：**
> 此外还有膳食推荐，根据营养缺口为食谱打分排序并配套运动方案；以及食物营养速查，支持 915 种食物的营养成分查询。

## 四、AI 技术亮点（5:00–6:00）

**画面：** 回到对话助手页，展开一条回答的「参考资料」和「工具调用轨迹」。

**旁白：**
> 最后介绍我们的 AI 技术亮点，主要有四点：
>
> 第一，RAG 检索增强。本地知识库包含科普文章、食物搭配辟谣和 915 条食物营养数据，共 900 多个检索单元。每次提问都会先检索知识库，把相关内容作为参考注入提示词，回答更准确、可追溯。
>
> 第二，规划执行型 AI Agent。面对简单问题，模型可以按需调用 7 个工具；面对“结合最近三天饮食安排减脂三餐”这类复杂任务，Agent 会先生成结构化计划，再逐步读取真实数据。每一步的待执行、执行中和完成状态都在界面可见；数据不足时还会进行一次受控重规划。我们展示的是行动计划和结果摘要，不展示模型隐藏思维过程。写入仍然必须由用户二次确认。
>
> 第三，反事实营养干预。点击“模拟今日优化”后，Agent 会比较控糖、补蛋白和均衡优化等方案，界面直接展示热量、糖、蛋白质和健康评分的前后变化。比如只把奶茶减半虽然糖下降了，但因为今日总热量本来就偏低，综合评分反而下降；因此系统推荐同时控糖、补蛋白和补纤维。这里的数值由本地营养规则重新计算，不是大模型编造，也不宣称医疗效果预测。
>
> 第三，三层降级机制。优先调用云端大模型；如果网络异常或 Key 未配置，自动回退到服务端 Mock；再不行就用本地知识库和规则引擎作答。保证任何环境下功能都不中断。
>
> 第四，密钥安全。API Key 只存在服务端的 .env 文件里，从不打包进浏览器产物，前端通过本地代理转发，避免密钥泄露。

## 录制注意事项

1. **分辨率**：录屏软件设置 1920×1080，浏览器窗口最大化，避免黑边。
2. **节奏**：旁白语速约每分钟 220 字，总字数约 1400 字，自然语速约 6 分半。
3. **字幕**：建议用剪映自动生成字幕，校对后导出。
4. **数据准备**：录制前先清空演示数据再重新记录几条，确保首页数据有内容、状态分布丰富（有达标有超标）。
5. **AI 可用**：录制前确认 `npm run ai:server` 已启动、API Key 已配置，避免识别和对话走降级模式。
6. **避免口误**：不要宣称「自研大模型」「训练准确率 XX%」，如实说明使用的是智谱开放平台的大模型 API，项目亮点在于 RAG、Agent 与本地可解释引擎的工程整合。
